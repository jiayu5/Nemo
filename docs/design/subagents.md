# Subagents 设计

## 目标与范围

M11 当前交付异步并行的只读分派：父 Agent 可以启动一组独立调查任务、继续自身工作，再查询、等待或取消子任务。原先同步只读闭环作为兼容入口保留，不再作为多 Agent 协作的完整交付目标。现行参数、限制、状态和事件以 [Subagents 参考](../reference/subagents.md) 为权威来源。

首版保持只读，先让多个任务独立检索和分析，再由父 Agent 整合结果。尚未处理共享工作区写入冲突、独立模型与后台任务；无需新增依赖或数据库迁移。

## Run 所有权与 Runtime 复用

每个父 Run 装配一个 Core SubagentManager，维护子任务记录、asyncio Tasks、并发 Semaphore 和共享模型调用预算。工具入口共用该管理器：批量创建立即返回 ID；查询只读快照；等待支持任意/全部完成及有界超时；取消等待清理。任务数量有限，排队任务也有总耗时限制。

异步批量创建先生成未发布的任务记录，并验证 ID 快照的输出限额，之后才注册任务、发出排队事件和创建 worker。这段过程没有 await 间隙，输出不足时整批拒绝，避免工具返回错误却留下运行任务。同步兼容入口仍等待单个结果，不要求先返回排队快照。

子任务继续使用 AgentRuntime，不复制 Agent Loop。各自拥有新的 ToolRegistry、ExecutionContext、消息状态和压缩引擎；继承冻结说明与 Skills 目录，强制过滤写入、Shell 和所有分派控制工具。背景由父 Agent 显式提供。

BudgetedModel 在模型调用前预留共享计数，父模型、子模型和压缩模型均使用同一包装器。计数更新没有 await 间隙，单事件循环内不会并发超发。包装器不拥有 transport 生命周期，外层 Server/CLI 仍管理原客户端。它限制请求次数，不宣称限制 token 或精确费用。

## 生命周期与事件桥接

ToolRegistry 识别工具可选的 runtime_scope，按身份去重；父 AgentRuntime 启动时初始化一次，finally 中关闭一次。关闭先拒绝新任务，然后取消并等待所有未结束子任务，再发父终态。交互 CLI 每个新 Run 重新初始化任务表和调用预算，旧 ID 不再有效。其他工具无需新增空实现。

各任务保存创建时的事件回调，父 Runtime 固定捕获创建调用 ID，避免父 Agent 继续工作后出现事件归属错误。排队与最终状态也进入原有父事件流；父 seq 连续、子 seq 独立连续。子终态不会触发父客户端终态检测。Activities 根据事件重建独立任务摘要，Trace 无需新 schema。

等待超时仅结束此次等待。单个子任务失败不取消兄弟任务，父 Agent可检查状态决定处理方式；父任务结束、取消或耗尽预算则清理全部剩余任务。结果聚合有界，完整子对话不进入父历史。最终报告在本 Run 内完整保存，状态和同步入口返回预览及长度；read_subagent_report 按字符分页并适配 JSON 输出限额，读页不消耗模型预算。报告以有界 subagent.report 分块进入父事件流，UI 拼接全文，历史回放不依赖仍在内存的管理器。

取消操作检查 worker 的取消状态，避免向已开始清理的任务重复发起取消。等待过程使用 shield；调用方在等待期间被取消时，先排空子任务并归结未启动任务的状态，再传播 CancelledError。Runtime 的 finally 也通过独立清理任务抵御重复取消，父终态只在全部清理完成后发出。

## 可检查的子任务过程

Activities 条目打开只读详情弹窗，保持父对话与滚动位置；详情直接读取父 SSE/Trace 中属于该 child_run_id 的事件，不创建子 Session、HTTP 端点或数据库迁移。Core 子 Runtime 可选记录有界模型响应和工具结果，管理器补充任务与最终报告，普通父 Runtime 的事件载荷不变。明细脱敏与限额以 [现行参考](../reference/subagents.md#子任务详情) 为准。

实时增量按子步骤拼接，非流式模型通过完成事件补齐输出；工具结果按调用 ID 对应。旧历史只展示实际保存内容。父对话和详情共享滚动跟随 Hook，用户离开底部后不被新输出拉回。

## 可配置步数与调用预算

AppConfig 的 subagents 节提供默认步数、步数上限和父子共享调用预算；Server 每次 Run、直连 CLI 启动时读取并注入管理器。管理器生成本次分派工具的 Pydantic 参数契约，默认值与 maximum 同时进入模型 schema 和服务端校验。父模型直接输出 max_steps，不解析自然语言建议。省略使用配置默认值；超过上限或类型错误在发布任务前拒绝整批。共享预算保持请求级硬限制，不为单个子任务预留独占额度。字段与生效规则以 [配置参考](../reference/configuration.md#subagents-预算) 为准。

## 步数耗尽时的报告

真实试用发现，子任务最后一步仍调用工具会以 limit_reached 退出且没有 output。子 Runtime 现在通过显式 finish_with_summary 模式，在现有预算内预留最后一步：移除工具 schema，注入汇总 Reminder（有可追加槽时），返回已确认发现与未检查项。即使模型忽略空工具列表，也拒绝执行最后一步的工具请求。

该路径保留 limit_reached 状态，不将部分结果伪装为完成；普通父 Runtime 默认行为不变，不额外添加模型请求。更早的共享预算耗尽、取消、超时仍按原边界处理。

## 子任务续轮

子任务结束不等于调查必须重来。父 Agent 拿到部分报告后往往只需追加一个方向，为此提供 `resume_subagent`：在本次父 Run 内让已结束的子任务带着已保存上下文再跑一轮。

续轮复用同一个 AgentRuntime 与其压缩 checkpoint，只追加该轮的 `prompt` 与 `max_steps`，不新建子 Run、子 Session 或数据库记录。选择这条路径而不是跨父 Run 持久化子任务，是因为父 Run 已定义完整的资源边界：共享模型预算、并发信号量和超时都在 Run 结束时统一收敛，把续轮留在 Run 内不需要额外的存储与恢复语义，也就无需数据库迁移。

准入沿用批量分派的顺序——先对拟议轮次做输出限额预检，通过后才改动轮次与状态、发出 `subagent.resumed`、创建 worker。因此预算耗尽或输出不足时续轮被拒绝，且不留下轮次自增、状态改写或孤立事件。为父 Run 保留的边界也一并适用：每轮独立授予步数预算但累计 `steps` 不清零，共享模型调用预算跨轮累计且不重置，父 Run 结束仍取消并等待续轮清理；每轮自排队起重新计总耗时。

报告按轮保存，使部分结果在各轮之间互不覆盖：`subagent.finished` 与 `read_subagent_report` 都以 `round` 定位，省略即当前轮。全部子事件 payload 附带 `round`，UI 据此分段显示续轮指令、步骤与报告。

## 验证与后续边界

离线测试用可控模型屏障证明任务实际重叠、父 Agent 继续进展和并发排队，不仅检查耗时。覆盖等待任意/全部、超时继续运行、单任务取消、总任务/调用预算、聚合结果、跨父 Run ID 拒绝、父终态前清理和事件归属。Server 验证持久化与 SSE 重放，CLI 保留兼容闭环；UI 验证任务状态摘要。

真实模型已完成一次三任务并行复验；规划质量、长期高并发、厂商限流策略仍需持续评估。后续考虑精确 token/费用预算、独立模型/角色、写入冲突协调、持久化子任务和专用任务管理；这些尚未作为当前交付能力。
