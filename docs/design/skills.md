# Skills 设计

> 状态：M10 已实现；真实模型触发与工作流程遵循质量待验收。

## 1. 目标与范围

为单 Agent 提供本地可复用工作流程，后续 Subagents 可复用同一端口与工具。首版提供技能目录、按需正文和文本资源加载、Server/CLI 装配及普通 Trace/历史追溯。现行格式、限额和接口以 [Skills 参考](../reference/skills.md) 为准。

不包含市场、远程安装、自动执行脚本、正文编辑 UI、完整 YAML、MCP 或 Subagents；未修改数据库 schema 或新增依赖。

## 2. 目录与上下文

Session 创建或重新打开时扫描内置、用户和项目目录；当前使用期间冻结名称、描述与读取标识，单独放入 ContextBuilder 的 Skills 区块，位于行为条款、说明文件之后、历史之前。不混入 AGENTS 文本，不加入绝对路径、时间或随机标识。

只将目录摘要提前提供给模型，正文和资源按需加载，解决“模型还不知道技能有哪些，就要先判断是否查找技能”的问题。技能匹配由模型基于描述完成；具名提示条款要求显式点名或匹配时先读取正文，不在 Runtime 中加入路由分支。

目录只存内存，重启和恢复允许重新扫描，接受稳定前缀变化而无需持久化过期目录。历史保留旧工具结果，当前目录与重新读取的正文反映本次加载版本。

## 3. 版本与资源

发现时读取有界 SKILL.md 校验格式和内容摘要，但不把正文提前提供给模型。读正文时校验摘要，变化则要求重新打开会话，避免目录描述与新正文混用。

按需读取正文时收集有界文本资源及摘要；资源读取先校验版本。修改资源后可再次读取技能更新资源清单。清单不是磁盘内容备份；文件仍可被用户修改，因此所有工具都重新检查路径和版本。

工具结果以普通 assistant/tool 消息进入历史，复用既有事件、Trace、持久化与 M7 压缩，无额外全局“已激活技能”状态。目录与输出超限明确失败，不通过静默截断隐藏缺失内容。

## 4. 分层与生命周期

- `core/skills.py` 定义不可变目录元数据、只读端口及纯目录序列化，不读取文件。
- `adapters/skills.py` 实现文件发现、受限格式、路径检查、版本与限额。
- `adapters/tools/skills.py` 实现三个只读工具，从 ExecutionContext 获取 workspace、超时和输出限制。
- `bootstrap.py` 唯一装配文件适配器和工具。
- SessionService 持有按 Session ID 缓存的目录；Run 启动时取得该目录引用，恢复时只替换未来 Run 使用的引用；删除 Session 释放缓存。
- `POST /sessions/{session_id}/resume` 显式刷新闲置会话目录；活动 Run 不切换。普通查询不产生隐式刷新。
- 直连 CLI 启动/恢复时扫描一次，交互轮次复用；transcript 只保存既有消息。

文件、SQLite、HTTP 均不进入 Core。Server、CLI 共享技能装配入口，Runtime Loop 不复制。

## 5. 权限与验证

技能提供工作流程，实际执行仍由既有工具与审批控制。只读加载不注册工具、不授予权限；用户级读取仅限专用技能根，普通文件工具边界不扩大。技能中的链接不会自动访问，脚本不会自动执行。

离线测试覆盖格式、冲突、分页、编码、符号链接、路径穿越、大小和输出限额、安全错误、版本变化、Fake Model 按需加载、既有审批、Server 连续 Run/恢复/重启、CLI transcript 恢复与 M7 压缩后重读。客户端验证覆盖恢复请求及既有 UI 流程。验证命令与结果见 [M10](../milestones/M10-skills.md)。

## 6. 后续

首版固定用户/工作区两个根，不继承父级技能；采用固定目录字符预算。真实模型的触发准确性、描述设计和工作流程遵循质量需独立试用。通用 YAML、热更新、更细粒度权限另行决定；管理入口见第 7 节。Subagents 后续可按自身 workspace、工具集合和预算复用此机制。

## 7. 技能管理入口（已实现）

顶栏 Skills 打开管理面板，展示内置、用户级和当前 Session 项目级技能的名称、描述、范围、诊断及正文详情。未选 Session 时仍可查看用户技能；不扫描其他历史工作区。

面板重新读取磁盘，不改变 Session 的冻结目录。每次打开面板自动扫描，无手动刷新按钮；采用紧凑双列条目，窄屏单列，点击查看详情。范围与完整项目路径收进悬停提示，移除重复范围标签和页脚说明。单文件导入入口已移除，因为完整技能可能包含 scripts、references 和 assets。

既有 Server 单文件预检和导入 API 保留兼容，前端不再调用。范围解析、排他保存和校验边界见 [Skills 参考](../reference/skills.md)。

## 8. 内置 Skill Creator（已实现）

采用内置技能指导对话创建，复用现有 Runtime 与文件工具。Bootstrap 将随包分发的提示资源目录注入 FileSkillCatalog 和 FileSkillManagementStore；其条目使用 builtin 范围，与用户、项目同名条目独立。内置正文和其他技能一样按需读取、校验版本，不增加 Runtime 路由或创建工具。

Creator 指导用途澄清、完整项目目录生成、资源按需组织及验证。现行调用、格式与范围以 [Skills 参考](../reference/skills.md#内置-skill-creator) 为准。用户级外部目录安装通过内置 Installer 的限定目标脚本提供，见下一节。

内置资源直接复用本机 Codex 的 `$skill-creator` 完整指令及辅助文件，保留原版结构和 Apache 2.0 许可，见 [官方创建文档](https://learn.chatgpt.com/docs/build-skills)及 [App Server 文档](https://learn.chatgpt.com/docs/app-server)。只替换产品名与默认路径，并在专门的适配参考中说明受限 front matter、现有工具、未实现的 UI 元数据策略及 workspace 边界；脚本使用 Nemo 解析器以避免生成不可发现的技能和新增 YAML 依赖。read_skill 增加显式正文分页，完整原版无需为默认输出预算删减。

离线验证覆盖 Bootstrap 默认发现、无 Session 的管理读取、跨范围同名、正文按需进入工具历史，以及既有 write_file 创建包含脚本、参考资料和资源的项目技能并在重新扫描后发现。Fake Model 验证调用链，不证明真实模型的触发和指令遵循质量。

## 9. 内置 Skill Installer（已实现）

复用 Codex 的指令与 GitHub 辅助脚本，沿用内置目录发现、按需资源读取和普通工具审批。辅助脚本是固定用户/当前项目根的完整目录发布入口，不增加 Runtime 路由、数据库状态或新的模型工具。具体参数、冲突处理、兼容性限制和生效时机见 [Skills 参考](../reference/skills.md#内置-skill-installer)。

离线验证使用隔离目录及伪 GitHub 下载，覆盖完整资源复制、用户/项目范围、重复安装、任意目标拒绝、不兼容元数据和符号链接拒绝；不修改真实用户技能或消耗模型 API。
